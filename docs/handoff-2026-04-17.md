# Handoff — Orchestrator end-to-end testing (2026-04-17)

## What Orchestrate is supposed to do

Orchestrate is a **meta-agent** (the "Orchestrator") that decomposes user requests and delegates to worker agents (Claude Code, Codex). The orchestrator does NOT write code. It plans, delegates, reviews, and decides.

### Orchestrator's end-to-end loop

```
User request → Route → Decompose → Delegate → Monitor → Review → Accept/Reject → Report
```

When a user says "open an orchestrator agent window" or "build me X", the orchestrator MUST be able to:

1. **Identify itself** as the Orchestrate Orchestrator (not "Claude" or "Codex")
2. **Call `orchestrate_spawn_agent`** — an MCP tool that creates a new worker thread
3. **See the spawn succeed** — receive `{agentId, threadId, workerId}` in the tool result
4. **Observe UI updates automatically** — thread appears nested under parent in sidebar, 3-pane layout activates
5. **Instruct the worker** via `orchestrate_send_to_agent`
6. **Wait for completion** via `orchestrate_wait_agent`
7. **Review work** via `orchesktrate_review_agent_work` (diff + checklist)
8. **Accept or reject** via `orchestrate_accept_work` / `orchestrate_reject_work`
9. **Report results** to the user in the orchestrator panel

- **Communication (5)**: send_to_agent, broadcast, transfer_context, ask_agent, share_file

### Codex Computer Use MCP binary — dead end

Tried to wire OpenAI's Codex Computer Use binary (`~/.codex/plugins/cache/openai-bundled/computer-use/1.0.750/...SkyComputerUseClient`) as an MCP server for Claude. Two-layer defense blocked it:

1. **macOS Launch Constraints**: Binary code-signed with "Parent Launch Constraints" — macOS AMFI kills the process unless parent is Codex. Bypassed by stripping signature and ad-hoc re-signing.
2. **TCC Apple Events authentication**: With stripped signature, `list_apps` returns `Apple event error -10000: Sender process is not authenticated`. TCC matches by (bundle, team, code hash). Ad-hoc has no team ID, so TCC has nothing to match against. User only has Apple Development certs (not Developer ID Application), so even signing with those failed to satisfy TCC.

**Conclusion:** Cannot wire Codex Computer Use to Claude without a Developer ID Application cert. Config removed. Use `claude-in-chrome` MCP (now wired and working) or the built-in `mcp__computer-use__*` tools instead.

## Gotchas learned

- **Server has no hot reload.** Any change to `apps/server/src/**` requires killing and re-running `bun dev`. This is THE single biggest footgun this session.
- **`gpt-5-codex` is not supported on ChatGPT-auth Codex accounts.** Use `gpt-5.4`.
- **`canUseTool` receives MCP-prefixed tool names** (`mcp__orchestrate__orchestrate_spawn_agent`) for tools that came via MCP. Any check against `ORCHESTRATION_TOOL_NAMES.has(name)` must strip the prefix first.
- **Old orchestrator threads are not idle.** They remain in the snapshot as "orchestrator" threadType forever, which makes the MCP server's snapshot-based fallback lookup pick the wrong one. The env var is the correct source of truth.
- **macOS LaunchServices treats `.app` dirs specially.** If you ad-hoc sign a binary inside a `.app` bundle and install it under a parent dir also named `.app`, Gatekeeper rejects it. Install under a plain dir (e.g. `~/.cua-patched/bundle/`) to bypass.
- **TCC (Apple Events) requires Developer ID Application signature** for `-10000: Sender process is not authenticated` to have a chance of resolving. Apple Development certs aren't enough.
